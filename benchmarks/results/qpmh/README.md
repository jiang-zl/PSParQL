# QPMH 仿真验证：YAGO2 的四条原始查询

主基线为未修改的 4079ce57544c1d72338c6af02ba9ecbc8b19f8b6。基线计时使用该提交单独编译的二进制；基线组数及图副本使用同一提交的独立观测构建。优化版为默认自动策略，四条查询均选择了基于剩余工作代价的边分桶。

## 方法

同一台 i7-13700KF，WSL2/Linux x86-64，MPICH 4.0，4 个 rank，每 rank 2 个计算线程。GCC 11.4，C++11，-O2，单机本地文件适配 HDFS 读接口。所有策略使用相同的输入和数据分区。生成器参数为 8 个 cohort、64 students、512 cast、8 films，共 105,008 条不同 RDF 三元组与 69,863 个 RDF 顶点。原始 data.nt 的 SHA-256 为 da3df8f85afd5561c79073ec79d6c76ef1e3af565473b0fc24432e55ceecec19。模拟图包含同名、共享演员表、单人电影及不同出生地。

每个查询每种模式有五轮计时，每轮随机化运行次序。加速比取基线中位数除以新版中位数。计时关闭绑定日志和诊断计数器，副本及扫描数另跑一次。原版根任务的实际组数会随线程调度略变。在小规模生成图上另用独立 Rasqal 引擎核对。主图参考值用三元组索引计算 Q1/Q2/Q4 的绑定多重数；Q3 对每部电影求演员姓名选择数之和的平方，再跨电影求和。

Q2 的主要收益是消除跨组重复。Q3 的原版在该图上已经没有重复三元组，新版保持这一点，通过共享演员集合上的投影、复用精确后缀和独立姓名分量的重数计算降低扫描。Q1、Q2、Q4 的时间接近原调度器的轮询粒度，微小耗时差不宜解释为稳定加速。QPMH 摘要与种子迁移也有成本，单独见流量计数。

## 调参与负对照

在较小的 62,000 三元组版本上试验签名及批上限。未满桶跨窗口继续接收种子，提高连向后续多输入求交的属性权重，最大批上限由 256 提至 4096。开发记录中，Q3 的跨组重复三元组随批上限增加从 186,368 降至 0。最终运行固定策略和阈值，没有按每一条查询事后挑最快模式。Q1、Q2、Q4 的学生/导师数据与调参图共享生成规律；这个结果不能证明跨数据集全局最优。

负对照采用 edge_workloads.py 的 disjoint 图，参数 classes=16、repeats=16、width=32、fanout=4。默认策略回退根模式，答案为 32,768，两种版本的重复三元组均为零；探测本身仍产生摘要及路由开销。

## 正确性

原始四条查询的独立 Rasqal 小图结果分别为 12、8、801、8。最终边执行器的 26 个用例在普通计数和逐绑定构建中各跑四种配置，共 208 项通过，覆盖 1、2、4 个真实 MPI rank，包含自环、反向、多谓词合取、角色可重用、空结果和独立叶子。任务还通过内存传输与磁盘格式的往返测试。一次早期并行启动两批本地 Hydra 作业时出现过单次非零退出，当次日志未捕获原因；同一用例独立复跑以及最终顺序套件均通过。

另用 GNU time 对每个 MPI 进程单独观测一次峰值 RSS，关闭所有图副本诊断。按查询记录四个进程峰值和其中最大值，见[内存实测](rss.csv)。这包含进程初始化和加载，不能将逻辑副本百分比直接解释为 RSS 降幅。
